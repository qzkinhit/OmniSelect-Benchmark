# LESS

Fidelity label: **published-core transfer** (text track only).

Source: Xia, Malladi, Gururangan, Arora and Chen, LESS: Selecting Influential Data for Targeted Instruction Tuning, ICML 2024. The official code (princeton-nlp/LESS) is MIT and was not copied.

Strategy name: `less`. Implementation: [`method.py`](method.py).

What is transferred: LoRA warm-up training on a random 5% of the pool for 4 epochs (rank 128, alpha 512, lr 2e-5, AdamW), per-record LoRA gradient features after every epoch, Adam preconditioning of the training-record gradients with that epoch's optimizer state, SGD gradients for the target records, normalization, random projection to 8,192 coordinates, and the score max over target domains of the sum over epochs of the cosine with the mean target gradient of the domain. The target set is the text reference sample (V_con under v2), with the five domains as target tasks. The order is cut to the per-domain token budget by the track.

Cost: the per-record gradients of SmolLM2-135M at context 512 take one forward and backward pass per record, 25,000 pool records per epoch, so four epochs take a few GPU hours per seed on one 48 GB GPU. LESS is a member of the unified text portfolio.

Device: the per-record gradient gathering, the Adam preconditioning with the stored moments, the count sketch (`index_add_` with the same seeded hash and sign vectors as the numpy sketch, so the projection is the same function) and both normalizations run on the model's device in float32. Each pool record moves only its `dim` sketch coordinates to the CPU, and the target-side sketches move once per epoch. `omniselect/tests/test_less_dtype.py` compares this path with the earlier CPU path on a bfloat16 toy model (sketches within relative 1e-4, identical top-16 of a 64-record pool). The measured seconds per record (pool and target) are written to `selection_info` in the candidate's `scores.json` and in `timings.json`. The selection can move at float tolerance against the CPU path, so runs that are compared with each other should use the same path. The CPU path left the GPU at about 13% utilization and took more than three and a half hours for the LESS selection of one text cell.

Batched per-record gradients: `grad_batch` records (default 16, `less_grad_batch` in the text TrackConfig) run in one right-padded forward and backward with an attention mask. Each record's loss is its mean token negative log-likelihood over its own predicted tokens, as in the one-record path, and the backward pass runs on the sum of the record losses. Records do not interact under causal attention with the padding mask, so the output gradient G_b of each LoRA branch at record b belongs to record b alone. A tensor hook on the branch keeps G_b, and the per-record gradients follow from the branch inputs by batched outer products, dB_b = scale sum_t G_bt^T z_bt and dA_b = scale sum_t (G_bt B)^T h_bt with z = h A^T, in float32. This is exact and needs no vmap (vmap over the Hugging Face Llama forward was not used). When the batched path raises, the one-record path runs, and `selection_info` records `grad_batch` and `gradient_path`. In float32 the batched and one-record gradients agree to a relative error of 1.5e-7 on the toy model. In bfloat16 they agree to 7e-3, the rounding difference of the batched and single-record kernels, and the top-16 of a 64-record toy pool is identical.

Numerics: the LoRA factors take the dtype and device of the base weight (bfloat16 when transformers 5 loads SmolLM2 in its config dtype, float32 with transformers 4.57), the LoRA branch is computed in that dtype, and the per-record gradients, their Adam preconditioning and the count sketch are cast to float32 before accumulation. The fine-tuning learner of the text track is unchanged.

Deviations: the LoRA adapter covers the q and v projections (the paper's LoRA covers all attention projections). The projection is a seeded count sketch instead of the dense Rademacher projector of TRAK, which has the same inner-product preservation in expectation and needs no projection matrix in memory. The epochs are weighted equally (the paper weights checkpoints by their learning rate, which is constant within the warm-up here). The model is the reference SmolLM2-135M of the text track, not an instruction-tuned LLaMA.
